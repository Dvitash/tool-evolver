# Tool Evolver V1.0.0 Release Notes

**Release Tag**: `v1.0.0`  
**Release Date**: August 17, 2026  
**Status**: General Availability (GA)  
**Parent Roadmap Epic**: `#47` (`Autonomous Tool Evolution Platform V1 Release`)  

Tool Evolver V1.0.0 marks the official production-ready General Availability (GA) release of the autonomous, privacy-safe developer tool evolution platform. This release delivers complete end-to-end support for automated session observation, opportunity clustering, pure-compute and brokered tool synthesis, sandboxed preactivation verification, real canary traffic routing, and multi-harness integration with Claude Code, Codex CLI, and Oh My Pi (OMP).

---

## Highlights & Architectural Milestones (REM-001 through REM-020)

### 🛡️ Fail-Closed Security & Sandbox Isolation
- **Fail-Closed Safety Gate ([REM-001](../release/release-evidence.md#authoritative-traceability-matrix))**: Real-time evaluation of tool security invariants before execution with automatic fail-closed blocking when invariants are unmet.
- **Broker-Only Filesystem Access ([REM-003](../release/release-evidence.md#authoritative-traceability-matrix))**: Strict kernel-level and process-level isolation preventing direct disk access from evolved tools; all workspace mutations are broker-mediated with symlink escape defense.
- **Non-Disclosing Secret References ([REM-004](../release/release-evidence.md#authoritative-traceability-matrix), [REM-005](../release/release-evidence.md#authoritative-traceability-matrix))**: Secrets are referenced via opaque descriptors (`$secret:NAME`) without leaking raw credential values to inference models, logs, or tool source code.
- **Canonical Command Execution Policy ([REM-006](../release/release-evidence.md#authoritative-traceability-matrix))**: Tool execution is bound to an explicit allowlist of approved binaries with path canonicalization and environment sanitization.
- **Preactivation Bytecode Verification ([REM-007](../release/release-evidence.md#authoritative-traceability-matrix))**: Mandatory TypeScript compilation, static AST policy checks, and behavioral sandbox probes before any tool artifact is loaded.

### ⚙️ Autonomous Synthesis & Durable Evolution Lifecycle
- **Opportunity Clustering & Transactional Handoff ([REM-008](../release/release-evidence.md#authoritative-traceability-matrix))**: Userspace session observation clustering repetitive developer workflows into actionable evolution opportunities.
- **Pure-Compute & Brokered Tool Synthesis ([REM-009](../release/release-evidence.md#authoritative-traceability-matrix), [REM-010](../release/release-evidence.md#authoritative-traceability-matrix))**: Automated generation of TypeScript/Deno tools with bounded inference repair loops and capability minimization.
- **Multi-Step Workflows with Compensation ([REM-011](../release/release-evidence.md#authoritative-traceability-matrix))**: Synthesis of multi-step tool workflows with variable bindings and automated rollback/compensation actions on failure.
- **Historical Replay & Evaluation Pipeline ([REM-012](../release/release-evidence.md#authoritative-traceability-matrix))**: Replay candidate tools against real past sessions with semantic diffing and automated benchmark scoring.
- **Durable Lifecycle Orchestrator ([REM-013](../release/release-evidence.md#authoritative-traceability-matrix))**: Crash-resilient state machine managing candidate evolution, retries, and dead-letter queues across transient network/service failures.

### 🌐 Deployment, Multi-Harness Support & Platform Qualification
- **Gateway Canary Routing & Instant Rollback ([REM-014](../release/release-evidence.md#authoritative-traceability-matrix))**: Local MCP Gateway dynamically shifts traffic to canary versions and triggers instant automatic quarantine upon abnormal error rates.
- **Multi-Process E2E Topology ([REM-015](../release/release-evidence.md#authoritative-traceability-matrix))**: Validated complete topology running as genuine OS subprocesses with real IPC/MCP transports and SQLite storage.
- **Zero-Dependency NPM Bootstrap ([REM-016](../release/release-evidence.md#authoritative-traceability-matrix))**: Single-command installation (`npx tool-evolver init`) with signed tarball downloads and platform user service registration.
- **Multi-Harness Qualification ([REM-017](../release/release-evidence.md#authoritative-traceability-matrix))**: 100% qualified integration across Claude Code, Codex CLI, and Oh My Pi.
- **5-Lane Platform Qualification Matrix ([REM-018](../release/release-evidence.md#authoritative-traceability-matrix))**: Verified install, systemd/launchd lifecycle, autostart, permissions, upgrade, rollback, and uninstall across Linux x64/arm64, macOS Intel/Apple Silicon, and WSL.
- **Cloud Staging & Resilience Qualification ([REM-019](../release/release-evidence.md#authoritative-traceability-matrix))**: Verified encrypted backup/restore rehearsal, 12-scenario chaos fault injection, and 24h soak testing (p95 latency < 50ms).
- **Signed Release Evidence & Provenance Attestation ([REM-020](../release/release-evidence.md#authoritative-traceability-matrix))**: Complete cryptographic manifest signing (Ed25519), CycloneDX 1.5 SBOM, SLSA provenance, and requirement-to-evidence traceability.

## Previous-Known-Good Rollback Instructions

In the unlikely event that an upgrade or active tool version encounters regressions:

### 1. Instant Tool Rollback
```bash
# Roll back a specific tool to its prior stable promoted version
tool-evolver repair --rollback-tool <tool_name>
```

### 2. Binary Rollback via Channel Metadata
```bash
# Roll back Tool Evolver daemon to the previous-known-good version (0.1.0)
tool-evolver upgrade --version 0.1.0 --force
```

### 3. Emergency Kill Switch
```bash
# Immediately disable all evolved tools while preserving base harness capabilities
tool-evolver repair --disable-all-evolved-tools
```

For complete recovery runbooks, refer to [Client & Cloud Rollback Procedures](rollback-procedure.md) and [Operator Runbooks](../operator/runbooks.md).
